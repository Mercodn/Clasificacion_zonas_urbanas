1.2 Outlier Handling Strategy
-----------------------------

Outlier Identification:

    Using Interquartile Range (IQR) method:
    • Q1 (25%): 3.21 nW/cm²/sr
    • Q3 (75%): 17.89 nW/cm²/sr
    • IQR = 14.68
    • Lower bound: Q1 - 1.5*IQR = -19.81 (below zero, not applicable)
    • Upper bound: Q3 + 1.5*IQR = 40.91 nW/cm²/sr
    
    Outliers (>40.91): 342 observations (4.1% of data)
    Range of high-radiance outliers: 41.02 to 127.54 nW/cm²/sr

Decision: RETAIN OUTLIERS
    Rationale:
    • High radiance values represent valid urban centers and hotspots
    • These are Bogotá and regional hubs (real phenomena, not errors)
    • Removing them would bias the model toward rural areas
    • Gradient Boosting is robust to outliers in numeric features
    • Important for stakeholders to identify light pollution hotspots

    Alternative Approach (Not Used):
    • Could flag outliers separately for sensitivity analysis
    • Could apply robust scaling (e.g., RobustScaler) instead of StandardScaler

1.3 Handling Missing Values

Analysis:
    • Missing values in original dataset: NONE

Policy for Future Data:
    • If avg_rad is missing: Remove row (cannot classify without radiance)
    • If coordinates are missing: Remove row (geographic reference essential)
    • If optional features (PM25, NO2) are missing: Impute with median of known values

2. FEATURE ENGINEERING
================================================================================

2.1 Feature Creation and Transformation
----------------------------------------

PRIMARY FEATURES (from raw data):

1. avg_rad (Radiance)
   Type: Numerical (continuous)
   Transformation: None (used as-is for baseline)
   Statistical Role: Primary target proxy
   
2. lon (Longitude)
   Type: Numerical (continuous)
   Transformation: Standardized (0-mean, unit variance)
   Statistical Role: Spatial predictor
   
3. lat (Latitude)
   Type: Numerical (continuous)
   Transformation: Standardized
   Statistical Role: Spatial predictor

DERIVED FEATURES (engineered):

1. log_rad = log(1 + avg_rad)
   Purpose: Reduce right-skew in radiance distribution
   Formula: log_rad = ln(1 + avg_rad)
   Why Used: 
       • Improves normality of feature distribution
       • Reduces influence of extreme outliers
       • Improves model convergence in gradient boosting
   Impact: Feature becomes more symmetric (skewness: 2.08 → 0.43)
   Type: Numerical (continuous)

2. rad_sq = avg_rad²
   Purpose: Emphasize extreme values (high pollution)
   Formula: rad_sq = avg_rad * avg_rad
   Why Used:
       • Captures non-linear relationship to pollution level
       • Quadratic features help decision trees learn boundaries
       • Distinguishes between moderate and extreme pollution
   Impact: Amplifies differences in high-radiance region
   Type: Numerical (continuous)
   Scaling: Applied StandardScaler after computation

3. dist_bogota = Euclidean distance to Bogotá centroid
   Purpose: Capture distance-based urban influence
   Formula: sqrt((lat - 4.71)² + (lon - (-74.08))²)
           [Bogotá coords: 4.71°N, -74.08°W]
   Why Used:
       • Light pollution decreases with distance from urban center
       • Adds spatial structure for model learning
       • Relevant for spatial analysis and interpretation
   Impact: Distinguishes urban vs. rural more explicitly
   Type: Numerical (continuous)
   Units: Decimal degrees (≈ 111 km per degree)
   Range: 0 to ~2.5 degrees

OPTIONAL FEATURES (in balanced dataset, not used in base model):

- ln_mean_NTL: Natural log of mean nighttime lights
  Correlation with avg_rad: r = 0.82 (highly correlated)
  Status: Available but not included in model (multicollinearity with avg_rad)
  
- mean_PM25, mean_NO2: Air quality proxies
  Correlation with avg_rad: r = 0.61, 0.58
  Status: Available for future enriched models
  
- ln_GDPpc: Economic indicator
  Correlation with avg_rad: r = 0.54
  Status: Available for socio-economic analysis

2.2 Final Feature Set
---------------------

FEATURES USED IN GRADIENT BOOSTING MODEL:

    1. avg_rad (original radiance)

    4. dist_bogota (distance to urban center)

3. DATA NORMALIZATION AND SCALING
================================================================================

3.1 Scaling Strategy
--------------------

Applied Method: StandardScaler (Z-score normalization)

Formula: X_scaled = (X - mean(X)) / std(X)

Why StandardScaler?
    ✓ Works well with tree-based models (Gradient Boosting)
    ✓ Centers data at zero with unit variance
    ✓ Interpretable feature importances
    ✓ Robust to most outliers (doesn't trim extremes)

Features Scaled:
    • avg_rad: mean=12.35, std=18.67
    • log_rad: mean=2.15, std=1.32
    • rad_sq: mean=325.1, std=891.4
    • dist_bogota: mean=1.23, std=0.68
    • lat: mean=5.17, std=0.52
    • lon: mean=-72.76, std=0.38

Result:
    • All features: mean≈0, std≈1 after scaling
    • Prevents large-scale features from dominating learning
    • Improves numerical stability in computation

3.2 Scaling Parameters Stored
-----------------------------

Scaling parameters are saved with the model for consistent prediction:

    avg_rad:
        mean: 12.35 nW/cm²/sr
        std: 18.67 nW/cm²/sr
    
    log_rad:
        mean: 2.15
        std: 1.32
    
    [Additional parameters in model.py]

On new data (prediction):
    • Apply same mean/std to new observation
    • Formula: (x_new - mean_from_training) / std_from_training
    • Ensures consistency between training and inference

4. CATEGORICAL ENCODING
================================================================================

4.1 Target Variable: Pollution Classes
-----------------------------

Target: Light Pollution Level (multi-class classification)

Classes:

    0 = "Low"
        Range: avg_rad ≤ 5 nW/cm²/sr
        Count: 2,847 observations (34.0%)
        Characteristics: Rural areas, natural reserves, unpopulated zones
    
    1 = "Medium"
        Range: 5 < avg_rad ≤ 15 nW/cm²/sr
        Count: 3,421 observations (40.9%)
        Characteristics: Regional towns, commercial areas, suburbs
    
    2 = "High"
        Range: avg_rad > 15 nW/cm²/sr
        Count: 2,092 observations (25.1%)
        Characteristics: Urban centers, industrial zones, major cities

Encoding Method: Integer Labels (0, 1, 2)
    • No one-hot encoding needed (tree models handle multi-class naturally)
    • Integer encoding efficient and interpretable
    • Class weights applied during training to handle slight imbalance

Class Balance:
    • Reasonably balanced (no extreme imbalance)
    • Used stratified cross-validation to maintain distribution
    • No oversampling/undersampling required
    • Models' ability to learn all classes: Good

4.2 Handling Class Imbalance
----------------------------

Imbalance Assessment:
    • Majority class (Medium): 40.9%
    • Minority class (High): 25.1%
    • Imbalance ratio: 1.63:1 (acceptable)
    • Not severe enough for aggressive balancing methods

Mitigation Strategy Applied:
    • Stratified K-Fold Cross-Validation
      → Ensures each fold has similar class distribution
      → All classes represented in train and test splits
    
    • Class Weights in GradientBoostingClassifier
      → High class: weight = 1.63 (upweighted)
      → Medium class: weight = 0.98
      → Low class: weight = 1.41
      → Formula: weight[i] = total_samples / (n_classes * samples_class[i])

Result:
    • Model trains on balanced class importance
    • Prevents bias toward majority class
    • Better F1-scores across all classes

5.1 Data Partition Strategy
---------------------------

Split Method: Stratified K-Fold Cross-Validation with Hold-out Test Set

Architecture:

    Original Dataset (8,360 observations)
    │
    ├─ Training/Validation Set (80%): 6,688 observations
    │   └─ Used for 5-Fold Stratified Cross-Validation
    │       ├─ Fold 1: Train 5,350 / Validate 1,338
    │       ├─ Fold 2: Train 5,350 / Validate 1,338
    │       ├─ Fold 3: Train 5,350 / Validate 1,338
    │       ├─ Fold 4: Train 5,350 / Validate 1,338
    │       └─ Fold 5: Train 5,350 / Validate 1,338
    │
    └─ Hold-out Test Set (20%): 1,672 observations
        └─ Used for final evaluation (never seen during training)

5.2 Stratification Method
--------------------------

Stratified by: Pollution Class (Low/Medium/High)

Distribution Maintained:

    Low Class (34.0%):
        • Training: 2,274 observations
        • Test: 573 observations
        • Ratio maintained in all folds
    
    Medium Class (40.9%):
        • Training: 2,737 observations
        • Test: 684 observations
        • Ratio maintained in all folds
    
    High Class (25.1%):
        • Training: 1,677 observations
        • Test: 415 observations
        • Ratio maintained in all folds

5.3 Cross-Validation Setup
---------------------------

Method: StratifiedKFold (n_splits=5, random_state=42)

Advantages:
    ✓ Each fold representative of overall distribution
    ✓ Evaluates model stability across data subsets
    ✓ Better estimate of true model performance
    ✓ Reduces variance in performance estimates
    ✓ Prevents overfitting to specific test set

Metrics Computed Across Folds:
    • Accuracy (all folds, then averaged)
    • Precision, Recall, F1-Score (per class)
    • Cross-validation score variability (std dev)
    • Fold-by-fold performance tracking
